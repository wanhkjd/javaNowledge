# 面试官：聚集索引和非聚集索引的区别

> 来源：B站视频 BV1fM4y1e7vt ｜ 主讲：徐庶老师

---

## 一、先厘清三个概念

- **聚集索引 = 聚簇索引**；**非聚集索引 = 非聚簇索引**——只是叫法不同，是同一种东西。
- 它们**不是一种「索引类型」**（区别于唯一索引、主键索引等），而是从**物理存储方式**来区分的。
- 一句话速记：**InnoDB = 聚集索引**，**MyISAM = 非聚集索引**。

---

## 二、从物理存储文件看区别

| 存储引擎 | 文件 | 说明 |
|----------|------|------|
| **InnoDB**（聚集） | `.frm` | 表结构（frm ≈ form） |
| | `.ibd` | InnoDB Data——**索引 + 数据聚合存在一起** |
| **MyISAM**（非聚集） | `.frm` | 表结构 |
| | `.MYD` | MyISAM Data——表**数据** |
| | `.MYI` | MyISAM Index——表**索引** |

- InnoDB：索引和数据**聚合**在同一个 `.ibd` 文件里 → 所以叫**聚集索引**。
- MyISAM：索引（`.MYI`）和数据（`.MYD`）**分开**存储 → 所以叫**非聚集索引**。

> 仅从物理存储方式，就能直接看出两者区别。

---

## 三、从底层数据结构（B+树）看区别

MySQL 索引的底层数据结构是 **B+树**，数据/指针都存在**叶子节点**。以查找 `id = 18` 为例：

### 聚集索引（InnoDB）
叶子节点里**索引和数据存在一起**。

- 检索路径：根节点 →（15 与 56 之间取指针）→（15 与 20 之间取指针）→ 定位到 18。
- 约 **3 次磁盘 IO** 即可，且叶子节点**直接拿到数据本身**，一棵树查完即得。

### 非聚集索引（MyISAM）
叶子节点**只保存数据的物理存储地址（指针）**，不含数据本身。

- 同样约 **3 次磁盘 IO** 在索引（`.MYI`）里定位到 18，但只拿到 18 的**存储地址**。
- 还需拿着这个指针，**再去数据文件（`.MYD`）里查一遍**，才能取到真正的数据。
- 因此非聚集索引的检索效率**比聚集索引更慢**。

---

## 四、核心区别总结

| 对比项 | 聚集索引 | 非聚集索引 |
|--------|----------|------------|
| 代表存储引擎 | InnoDB | MyISAM |
| 索引与数据 | 存在一起（`.ibd`） | 分开存储（`.MYI` + `.MYD`） |
| B+树叶子节点存什么 | 索引 **+ 数据** | 只存**数据的物理存储指针** |
| 检索数据 | 一棵树直接拿到数据，**更快** | 拿到指针后还要回数据文件再查一次，**更慢** |
| 更新代价 | **更大**（见下） | 相对较小 |

### 关于「更新代价更大」
- B+树是按**顺序**排好的，若某个索引值被更新，可能触发**重排**，代价较大。
- 但聚集索引通常建立在**主键 id** 上，而主键一般**不会修改**，所以这个缺点**基本不存在**。

## 五、补充说明

> 「InnoDB = 聚集、MyISAM = 非聚集」是面试常用的**引擎级简化记法**，便于区分两种物理存储方式。严格来说「聚集/非聚集」描述的是**单个索引**：InnoDB 的**二级（辅助）索引**其实也是非聚集的，叶子节点存的是主键值，查完还要用主键**回表**到聚集索引取整行数据。理解主线以视频讲解为准即可。
